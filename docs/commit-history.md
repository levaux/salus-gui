# Commit History

Version history for the salus-gui console, grouped by major/minor release. The `"version"` in the
root `package.json` is the single source of truth; bump it with each versioned commit and add a row
here. Non-versioned commits (`docs:` / `proto:` / `test:` / `infra:` / `chore:` / `fix:`) get no
row — `git log` carries them.

---

## v0.1 — Workspace Scaffold (released as `v0.2.0`, 2026-09-08)

The first release train ([docs/plans/completed/001-salus-gui-repo.md](plans/completed/001-salus-gui-repo.md)), taking
the repository from planning apparatus to a **walking skeleton**: every layer present, CI green on
a fresh checkout, and one genuinely live panel — fleet status + aggregated logs — working against
the deterministic mock over a real socket.

Six stages, each a versioned commit, in dependency order — toolchain, then the proto pipeline
everything else is typed by, then the data layer, then the fleet double that makes offline
development possible, then the bridge, then the app that proves the path end to end. The order was
not incidental: every stage after the first had something real to check against, which is why the
defects listed below were found by gates rather than by reading. What the train did **not** do is
also deliberate — no grid library, no state-management dependency, and Health/Therapy/Protocol
mock doubles left for the panels that will consume them, because a fixture invented before its
consumer exists is shaped by guesswork.

One honest note on the train's close: `v0.1.6` was committed and pushed with a red `eslint` and a
seed-dependent test failure, reported green. The gate script used `set -e`, which does not abort
in the agent shell, so it printed a success banner after a gate had already failed. Both were
fixed before this release; the rule in CLAUDE.md now names `&&` as the only verified chaining.

| v0.1.6  | **`apps/web` + the `ui-kit` seed — the walking skeleton closes.** A SvelteKit SPA (`adapter-static`, no SSR — everything on screen is live fleet state, so there is nothing a server could render that would still be true on arrival), a nav-rail shell whose disabled destinations name the plan that builds them, and the proving panel: the fleet registry and the aggregated log feed. Between them they exercise the whole path and both reconnect contracts — the registry re-reads and **evicts** deregistered services (Resnapshot), the log feed resumes by `seq` (SeqResume), and both are acquired through the store registry so navigation reuses live feeds (Linger). `ui-kit` ships five components; `DataGrid` is deliberately a plain table, because the seam is the point and a grid library before a measured need is a cost paid on every load. Formatting never fabricates: an absent value renders as an em-dash, never a plausible zero. **`svelte-check` earned its place immediately** — added as a distinct CI gate, it caught a wrong vite plugin import that would have stopped the dev server booting, plus two type errors `tsc` structurally cannot see. `infra/up.sh` gains the `web` component and a `--direct` flag (the SPA calls the bridge over one h2 connection instead of Vite's HTTP/1.1 proxy, which silently stops opening streams past the browser's ~6-per-origin ceiling). Verified end to end against the running stack: the SPA serves, unary RPCs reach the fleet through the proxy, and a browser-shaped client resumed the log stream at exactly seq 5 after seeing 1–4. CI gains `check`, `test` and `build`. 163 tests.                                                                                                                                                                                        |
| v0.1.5  | **`apps/bridge`: `salus-bridged` (`:56400`).** The browser's only counterparty: an h2/TLS server carrying `/rpc` (generic Connect ⇄ gRPC forward), `/kv` (workspaces, saved views) and `/bridge/*` (info, audit, the read-only switch). TLS is refused-without rather than optional, because browsers only multiplex h2 over TLS and the failure mode without it is panels that hang. Request headers cross **verbatim** — the reason `salus-log-since-seq` resume needs no special-casing here — minus only the connection-specific headers HTTP/2 forbids and the framing headers the upstream transport sets itself. Client- and bidi-streaming are skipped by rule: forwarding one would mean the bridge originates an Edge ingest session on a browser's behalf. Three guards, each tested: read-only refuses every mutating RPC fleet-wide while reads keep working; the browser-supplied `salus-admin-target` is pinned to the site host or loopback, so the bridge cannot become an open proxy; and KV names admit no separator or dot, making traversal unrepresentable. Client disconnects (`CANCEL`/`INTERNAL_ERROR`/missing status) are classified as routine and logged as one quiet line. **Two real defects surfaced and were fixed**: the mock bound one port while the bridge rebases each service to its own, so only Network was reachable — the mock now binds the whole rebased set, one listener per service, destroying sessions on close so a long-lived stream cannot hang teardown; and the mock answered Admin from a header the bridge correctly strips, so every per-service drawer reported the wrong process — each listener now answers **as** the service it fronts, matching a real fleet where a Component serves Admin only for itself. An 8-test integration suite drives the whole path on a real socket. 150 tests in total. |
| v0.1.4  | **`@salus-gui/mock-salus`: the deterministic fleet double.** One h2c Connect hub (`:56800`) answering Admin, Network and Session for the whole six-service fleet — `connectNodeAdapter` serves Connect, gRPC and gRPC-Web on the same routes, so the bridge's real `createGrpcTransport` talks to it unmodified. Every value is a pure function of `(seed, service, tick)`, so a run is byte-identical and a window slice is independent of how it was reached. **The mock's world follows the request**, tested per case: `salus-admin-target` picks which Component answers, `salus-log-since-seq` replays strictly newer frames, `include_closed` filters the roster, and an unknown target is `NOT_FOUND` rather than a fabricated healthy row. Mutations are observable — ejecting flips the row to `ERROR` (an operator's act, distinct from an expiry's `STOPPED`) and re-ejecting revokes nothing and says so. The seeded fleet is deliberately not all-green. Six of the 30 tests drive the hub over a real socket with a real gRPC client, which is what makes "the same code connects to the real fleet unchanged" tested rather than intended; that test caught a genuine bug, `port: 0` reporting the requested port instead of the bound one. **Health, Therapy and Protocol doubles are deferred to the panels that consume them** (`v0.2.5`/`v0.2.6`) — inventing query shapes before a consumer exists produces fixtures shaped by guesswork, the very disagreement this stage guards against. 109 tests in total.                                                                                                                                                                                                                                                                                                                                 |
| v0.1.3  | **`@salus-gui/theme` + `@salus-gui/streams`.** Theme ships scheme-agnostic tokens plus light/dark and the environment band, with the two colour scales driven by Salus's own closed catalogs — a token per `Salus.Admin.LogLevel` member (all eight, ALARM distinct from ERROR) and per `Salus.Common.ServiceStatus` (DEGRADED distinct from ERROR, because a degraded service is still serving); `applyTheme` is the only writer of `data-theme`/`data-env`, and `scheme: 'system'` removes the attribute rather than freezing a computed value. `mock` is a first-class environment beside dev/staging/prod, and an unrecognised environment falls through to the production treatment deliberately. Streams is the framework-lean data layer pinning **three** reconnect contracts: **SeqResume** (`salus-*-since-seq` headers, resumed from the last message), **Resnapshot** (subscribe-then-snapshot ordering, `applySnapshot` evicting stale keys, a failed snapshot failing the whole connection), and **Linger** (ref-counted acquisition where a released feed stays alive ~45 s, so navigation reuses streams instead of re-snapshotting — placed in this package rather than the app so the contract is testable). `isFatalConnectError` treats `PERMISSION_DENIED` as permanent because that is the shape a Session ejection takes. `ConflatedTable`'s keyed keep-latest is documented as the ReplacingMergeTree dedup and tested as such. 45 tests here, 79 in total.                                                                                                                                                                                                                                                                                                                                                                                 |
| v0.1.2  | **`@salus-gui/proto`: vendoring pipeline, codegen and catalogs.** `tools/sync-protos.ts` vendors the 10 `Salus/*.proto` files from the sibling repo and pins them in `salus-commit.lock` (SHA + per-file sha256); `--check` hashes the vendored copies rather than the source, so the drift gate needs no Salus checkout. buf v2 + protoc-gen-es v2 generate into an **untracked** `src/gen` via the package's `postinstall`, and `.buf-image-prev.binpb` is committed as the wire-compat baseline — recorded state, not derivable output. Three hand-written modules: `well-known.ts` (the Timestamp/Decimal choke point — bigint throughout, never `number`), `services.ts` (the 8-service catalog, `methodsOf()` mapping descriptor local names to wire proto names, `isForwardable()` refusing the Edge ingest bidis), and `mutating.ts` (the read-only guard's curated allow-list, over-listing deliberately). CI gains the drift gate, `buf breaking`, `typecheck` and `test`. Verified: 34 tests pass, both proto gates proven non-vacuous (a renumbered `Decimal.unscaled` fails `breaking`; an edited vendor file fails the drift check), and the catalog drift test caught a real defect during authoring — the mutating set had been written against descriptor keys (`drain`) rather than wire names (`Drain`). Pinned at Salus `2470b82` (v0.8.5).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## v0.0 — Bootstrap

The pre-scaffold state: the repository exists, carrying the planning and agent-management
apparatus (CLAUDE.md, `.claude/`, `docs/plans/` + INDEX, this file) but no product code — and
therefore no `package.json` to version, so the bootstrap ships as `chore:` commits and this
section has no version table. The `v0.1.x` series opens when
[docs/plans/completed/001-salus-gui-repo.md](plans/completed/001-salus-gui-repo.md) starts — the workspace scaffold, the
proto vendoring pipeline, the bridge, and the SPA shell.

The second bootstrap commit converted the plans register to the location-based lifecycle
(`backlog/` unnumbered → `NNN-<name>.md` at promotion → `completed/NNN-<name>.md`, numbers never
reused) and landed its tooling: `tools/plans.py` (sync / render-index / check / move — moves a
plan AND rewrites every inbound reference in one pass) and `tools/check-plans.py` (the register
lint: numbered ⟺ listed, `**Status**:` lines, backlog freshness, no dangling plan links).
