# Plan Index

Single source of truth for the lifecycle state of every plan in `docs/plans/`. The agent updates
this file on every state transition (see [the lifecycle ritual in CLAUDE.md](../../CLAUDE.md#plans-lifecycle)).

## States

A plan is in exactly one of four states, and each is visible from the filesystem alone:

- **backlog** — written, not started. Lives in `docs/plans/backlog/`, **unnumbered**, and has no
  row in the tables below. It appears in the generated `## Backlog` section further down. There
  is nothing to order: the backlog is a pool, and ordering only exists once work starts.
- **running** — promoted. Takes the next sequence number, moves to `docs/plans/NNN-<name>.md`,
  and gains a row under `## Running`.
- **parked** — running work on hold. Keeps its number and its location; only the row moves, to
  `## Parked`.
- **completed** — shipped. Moves to `docs/plans/completed/NNN-<name>.md` keeping its number, and
  the row moves to `## Completed`.

**The invariant: numbered ⟺ listed here.** A number is proof a plan was promoted to real work,
and this file is the register of allocated numbers. Numbers are allocated at promotion, in the
order work actually started, and are never reused, renumbered, or given up — including when a
plan completes, which is precisely when it has accumulated the most inbound references.

Every table below reads **newest first** — the highest `Seq` at the top, `001` at the very
bottom. The next free number is one above the maximum allocated `Seq` across Running, Parked and
Completed; a running plan can be newer than the first completed row.

## How to update this file

Every transition is the same two steps: **edit the row, then run the tool.**
`tools/plans.py sync` reads this file and makes the tree obey it — the move, the rename, and the
rewrite of every inbound link in the repository. Never move a plan file by hand; references
accumulate across `docs/`, the plans themselves and (once the scaffold lands) `packages/` and
`apps/`, and `docs/commit-history.md` alone will carry one per versioned row.
`tools/check-plans.py` is the lint that holds all of it: register consistency both ways, the
`**Status**:` line in every plan, backlog freshness, and every link into `docs/plans/` or
`research/` from anywhere in the repo.

**Writing a plan (→ backlog):**

1. Write `docs/plans/backlog/<name>.md` with `**Status**: backlog` under the title.
2. `tools/plans.py render-index` — it appears in `## Backlog` above.
3. No row, no number. Nothing else to do.

**Promoting a plan (backlog → running):**

1. Add a row under `## Running` with the **next free number**, state `running`, and today's date
   in `Started`. Point the link at `NNN-<name>.md`.
2. `tools/plans.py sync`.
3. Update `**Status**:` in the plan to `running`.
4. Add a one-line entry to [`## Active Plans` in CLAUDE.md](../../CLAUDE.md#active-plans).

Promotion is the point at which a plan is checked against the current architecture — a plan that
has been sitting in the backlog does not get picked up stale.

**Completing a plan (running → completed):**

1. Move the row to `## Completed`: state → `completed`, fill `Completed`, populate
   `Architecture docs updated`. Point the link at `completed/NNN-<name>.md`. **The number does
   not change.**
2. `tools/plans.py sync`.
3. Update `**Status**:` to `completed`.
4. Edit the affected `docs/*.md` so they reflect the shipped state, and record the shipping
   version in [docs/commit-history.md](../commit-history.md).
5. Remove the entry from `## Active Plans` in CLAUDE.md.

**Parking a plan (running → parked):**

1. Move the row to `## Parked`: state → `parked`. Keep the original `Started`.
2. Annotate `Architecture docs updated` with why, and the resume condition.
3. Update `**Status**:` to `parked`.
4. Remove the entry from `## Active Plans` in CLAUDE.md.

No file moves — a parked plan keeps its number and its location. Resuming moves the row back to
`## Running` and nothing else. A plan that was never started is not parked; it belongs in the
backlog, unnumbered.
